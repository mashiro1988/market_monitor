# 板块轮动 · 净资金流入（主动买入−主动卖出）设计稿

日期：2026-08-07
状态：设计定稿（与用户四轮问答敲定口径）
前置阅读：docs/remote_data_format.md（BMAC 数据格式）、docs/specs/remote_data_integration.md（板块一期）

## 1. 背景与目标

板块轮动页现在只有涨跌维度（1h/24h/7d/30d 均值+中位数）。本次给板块榜单和成分币钻取
各加一组"净资金流入"读数，回答"钱正在流进/流出哪个板块"，并支持价量背离观察
（价涨钱出=出货信号，价平钱进=吸筹信号）。

数据原料是币安 K 线自带的 `taker_buy_quote_asset_volume`（主动买入额，吃单方向为买的
成交额，USDT 计价）。这是交易所逐笔记录的精确数，不是 A 股软件按单子大小估算的
"主力资金"。原料已存在于 BMAC 数据服务器的单币文件中，但未进入本项目拉取的宽表——
本设计的主体工作是把数据管道补齐这一截。

**用户已拍板的四个决策：**

| 决策点 | 结论 |
|---|---|
| 市场口径 | 现货、永续**分开算，永不混加**（现货=真金白银，永续=杠杆情绪，量级差数倍） |
| 指标形态 | 绝对额（USDT）+ 强度比率（净流入÷总成交额）**都要** |
| 数据管道 | **方案一**：给服务器端 BMAC 宽表生成代码打纯增量补丁 |
| 附加要求 | 补丁结果要有**自动化验证逻辑**（部署验收 + 持续勾稽两道闸） |

## 2. 指标口径

### 2.1 公式

```
单币单根 1h bar：
  净流入 = 主动买入额 − 主动卖出额
         = taker_buy_quote − (quote_volume − taker_buy_quote)
         = 2 × taker_buy_quote − quote_volume        （单位 USDT）

窗口值（1h / 24h / 168h / 720h，与涨跌列四档完全对齐）：
  窗口净流入   = 最近 N 根 bar 净流入求和
  窗口总成交额 = 最近 N 根 bar quote_volume 求和

强度比率 = 窗口净流入 ÷ 窗口总成交额     （范围 −100% ~ +100%，币级、板块级同式）

板块级（现货、永续各自独立计算）：
  板块净流入   = Σ(成分币窗口净流入)
  板块总成交额 = Σ(成分币窗口总成交额)
  板块强度     = 板块净流入 ÷ 板块总成交额   ← 成交量加权，不用成分币比率简单平均
```

### 2.2 成员集合与涨跌列的差异

涨跌列每币只取一个市场（现货优先缺补永续）。资金流是**两条独立口径**：

- 现货流：板块内所有**在现货宽表有列**的成分币求和
- 永续流：板块内所有**在永续宽表有列**的成分币求和
- 两个集合允许不同（如某板块 30 币有现货、35 币有永续），各自的覆盖币数
  （`spot_flow_tokens` / `swap_flow_tokens`）落库并在前端悬停展示

板块行的存在性仍由涨跌口径决定（`MIN_TOKENS_PER_SECTOR` 不变，资金流永不创造新行）。

### 2.3 边界约定

- **部分窗口**：新上市币在窗口内只有部分 bar，按实际存在的 bar 求和（真金实银就算数）；
  净流入与总成交额取自同一批 bar，强度比率内部自洽。整个窗口无 bar 的币不参与该窗口聚合。
- **快照对齐**：资金流与涨跌用同一个 `as_of`（现货/永续最新 bar 的较早者），沿用
  `_slice_close_as_of` 现有逻辑，不会出现"价格是 10 点的、资金流是 9 点的"。
- **跨年短窗**：宽表按自然年分文件，每年 1 月头几周 720h 窗口缺去年数据——这是涨跌列
  今天已有的既有行为，资金流保持一致，本次不扩大范围。

## 4. 服务器补丁细节（改动①）

文件：数据服务器 `/root/data_center/bmac/preprocess.py`（本仓库镜像
`scripts/server_src/preprocess.py` 同步更新留档）。该文件已有历史本地补丁先例
（资金费率对齐处的"修改后的代码"注释），非首次改动。

两处纯增量修改：

1. `PIVOT_COLUMNS`（第 18 行）追加 `'quote_volume', 'taker_buy_quote_asset_volume'`
2. `make_market_pivot()` 对这两列各透视一个矩阵，spot 和 swap 的返回 dict 都追加
   键 `'quote_volume'`、`'taker_buy_quote_asset_volume'`（键名与列名一致，零映射层）

**容错要求**：切片处改为对缺列宽容（`df.reindex(columns=PIVOT_COLUMNS)` 语义：缺列补
NaN 而不是 KeyError 炸掉），防备 data_api 备用源个别文件缺这两列时拖垮整个预处理——
预处理停产会波及交易框架供数，此处宁可缺数不可崩溃。

**影响评估**：宽表文件约 20MB → 约 33MB（+2/3 键），拉取多几秒；旧键一个不动，
对既有消费者（交易框架）向后兼容。

## 5. 自动化验证（两道闸）

### 5.1 T0 部署验收脚本（一次性）

`scripts/verify_taker_pivot_patch.py`——独立 pandas 脚本（不依赖本项目代码），
scp 到数据服务器用其自带 python 跑，输出 PASS/FAIL 报告 + 非零退出码：

1. **结构**：新键存在；行索引、列集合与 `close` 矩阵完全一致（spot、swap 各查）
2. **抽样勾稽**：随机抽 ≥10 币 × ≥50 时点，宽表值 vs 对应单币原始 pkl 的
   `quote_volume` / `taker_buy_quote_asset_volume` 逐值核对（容差 1e-6）
3. **回归勾稽**：加载补丁前备份的宽表，在重叠时间段断言 `open`/`close`/`vwap1m`
   （及 swap 的 `funding_rate`）逐值不变——证明"只加列、没碰旧数"
4. **备用源体检**：抽查 data_api 目录若干单币文件确认两字段存在（评估 §4 容错的
   实际触发概率）

### 5.2 持续勾稽门（每小时，scanner 内）

新增校验函数（sector_scanner 内，spot/swap 各自过闸，一边失败不连坐另一边）：

| 检查 | 规则 | 失败含义 |
|---|---|---|
| 键存在 | 两个新键都在 pivot dict | 补丁未生效/被升级覆盖 |
| 时间对齐 | 新键矩阵 index 与 close 完全相等 | 半写/陈旧数据 |
| 恒等式 | `0 ≤ taker_buy ≤ quote_volume` 逐格（相对容差 1e-6），违规格子占比 ≤ `FLOW_IDENTITY_VIOLATION_MAX_RATIO` | 数据串列/损坏 |
| 空值一致 | 最新 bar 上 quote_volume 的 NaN 占比 − close 的 NaN 占比 ≤ `FLOW_NAN_GAP_MAX` | 新字段大面积缺数 |

**失败策略**：该市场当轮资金流全部写 `None`（涨跌照常产出），并按
`services/price_source_monitoring.py` 的 marker+冷却模式发一条告警
（marker=`flow_gate:{market}`，冷却 60 分钟，走既有 alert_logs 通道）。

新增配置常量（config.py，均为新参数，不动任何已校准值）：
`FLOW_IDENTITY_VIOLATION_MAX_RATIO`（默认 0.001）、`FLOW_NAN_GAP_MAX`（默认 0.05）、
`FLOW_GATE_ALERT_COOLDOWN_MINUTES`（默认 60）。

### 5.3 兼容性保证（上线顺序安全）

scanner 读不到新键时（补丁未上/已回滚）：勾稽门第一条失败 → 资金流字段全 `None`
→ API 返回 `flows` 内全空 → 前端显示"—"。**本项目代码可以先于服务器补丁上线**，
任何时刻回滚服务器补丁也不炸。

## 6. 存储与迁移（改动③）

`sector_returns` 表加 18 列（全部 nullable）：

- 16 × FLOAT：`{spot,swap}_net_{1h,24h,168h,720h}`（窗口净流入，USDT）、
  `{spot,swap}_qv_{1h,24h,168h,720h}`（窗口总成交额，USDT）
- 2 × INTEGER：`spot_flow_tokens`、`swap_flow_tokens`（两口径覆盖币数）

强度比率**不落库**（= net ÷ qv，读时现算，存了反而多一处要勾稽的冗余）。

迁移沿用 `database.py::_ensure_sqlite_schema` 里已有的 sector_returns 补列分支
（该分支现在只会加 FLOAT，需小改支持两根 INTEGER 列），幂等、线上无感。

## 7. API 契约（改动⑤）

`SectorLeaderboardRow` 与 `SectorTokenRow` 增加嵌套字段（pydantic 模型
`SectorFlowSide`）：

```jsonc
// 板块行
"flows": {
  "spot": { "tokens": 31, "net_1h": 1234.5, "net_24h": ..., "net_168h": ..., "net_720h": ...,
             "qv_1h": ...,  "qv_24h": ...,  "qv_168h": ...,  "qv_720h": ... },
  "swap": { ... }   // 结构同上；整侧无数据时该侧为 null
}
// 成分币行：同结构，无 tokens 字段；该币缺哪个市场哪侧为 null
```

强度比率由前端现算（`net / qv`，`qv > 0` 时才显示），少传 16 个冗余字段。
钻取的币级资金流读时从宽表现算（与涨跌同构，不落库）；币的现货列名与永续列名
经 `normalize_pivot_symbol` 归一后对到同一行。

## 8. 前端（改动⑥）

- 榜单表加 4 列：**资金 1h / 24h / 7d / 30d**。每格两行（沿用中位/均值堆叠样式）：
  上=现货 `+$46.2M · 12%`（净流入 · 强度），下=永续同格式；按净流入的**正负号**着色
  （沿用涨跌列的红涨绿跌色板；0 或缺失显示"—"，不着色）
- 格悬停 title：两口径覆盖币数 + 窗口总成交额
- 钻取表同加 4 列，同格式；该币缺哪个市场哪行显示"—"
- 排序下拉加 4 项：现货 24h 净流入、永续 24h 净流入、现货 7d 净流入、永续 7d 净流入
  （客户端排序，沿用现有 compareDescNullsLast；强度排序本期不做）
- 金额缩写：`$980K / $46.2M / $1.2B`，负数 `-$…`；强度取整百分比带符号

## 9. 测试计划

**pytest**（新增 tests/test_sector_flows.py 为主）：
- 计算正确性：合成小宽表手算核对（单币窗口求和、板块两口径聚合、部分窗口、快照对齐）
- 勾稽门四类失败路径：缺键 / 时间错位 / 恒等式违规超阈 / NaN 缺口超阈 →
  断言资金流为 None 而涨跌照常、告警走冷却
- 迁移：18 列自动补齐且幂等（重复跑不炸），参照 tests/test_behavior_daily_migration.py
- API 序列化：flows 嵌套结构、整侧 null

**vitest**：金额缩写格式化（K/M/B、负号、零）、强度计算（qv=0 不显示）、
FlowCell 缺侧渲染。

## 10. 上线顺序与回滚

1. 本项目全量上线（scanner 容忍缺键，页面资金流列显示"—"，其余照常）
2. 数据服务器：备份 `preprocess.py` → 打补丁 → 重启 BMAC 进程
   （选在整点写入周期刚结束的安静窗口操作）
3. 跑 T0 验收脚本 → PASS 才算部署完成
4. 盯一个整点周期：确认新宽表落地、mmon.top 拉到、页面出数、告警通道无 flow_gate
5. 回滚预案：还原备份文件 + 重启 BMAC（秒级）；本项目侧自动退化为"—"，无需动作
