## 0. 定位:二期拆成 A、B 两件套,本稿只管 A

用户对二期的真实诉求与 v0.3 的设想**方向相反**:v0.3 是"新闻里发现叙事→映射资产→等价格验证"(正向);实际痛点是"币安上某币突然被拉起来,到底为什么"(反向归因)。反向归因正是一期窗口标注的认识论——BTC 价格窗口找 driver 新闻——推广到任意币的异动。

据此二期拆为两个子项目,各自独立 spec→计划→实施:

- **A. Web3 快讯 + 加密事件池(本稿,先行)**:供给侧。接入加密新闻源、独立打分口径、事件池加 crypto 类型。与宏观线同构复制。
- **B. 异动币归因研究(另立设计稿,后行)**:需求侧。单币异动发现 + "为什么拉"的归因研究页。B 依赖 A 的新闻库先攒几周数据。

v0.3 的叙事/资产映射证据链/声量×价格四象限**不删、推后**:等归因数据积累后,"哪些异动共享同一个 driver 事件"会让叙事自下而上浮现,届时再定要不要模型参与——这也绕开了"模型日批 vs 一期人工立案原则"的矛盾。

BlockBeats **取全量、中文**(lang=cn,约 150-250 条/天)而非仅重要档:B 要归因的恰恰是小币,小币新闻基本在非重要档;只取重要档等于掐断 B 的原料。

**MCP 与采集管道的分工**:BlockBeats 官方出有 MCP 服务器(npm 包 blockbeats-mcp,背后即 Pro API;社区版 kukapay/blockbeats-mcp 包的是老接口,已随之失效)。MCP(=给 AI 助手接外部数据的标准接口)是对话场景的交互查询用的;**采集管道不经 MCP,直连 Pro API 的 HTTP 接口**——5 分钟轮询是服务器后台行为,不需要也不该架一层 AI 中间件。同一把 key 将来可顺手把官方 MCP 装给 Claude 做每日复盘时的现场查询,可选不急。Pro API 另带一批官方数据端点(BTC ETF 流量/稳定币市值/恐贪指标/合约持仓等),本期不接,将来做旁证列时是现成的官方口径。

### 1.2 机制:全部复用现有管道,零新造

配置表加源、5 分钟扫描、源内去重、游标盖章、失败退避,照旧。**跨源不去重**——多家报同一件事,重复本身是将来的声量信号。**不回填历史**:从接入日起算(BlockBeats 可翻页到历史,但补进来全是未评分存量,徒增混乱)。

### 1.3 新增字段:市场归属(market)

新闻入库时按源写死(加密源→crypto,现有源→macro)。这是打分分流、挂接分流、页面分流的总开关,也是 B 预埋第一件。

## 2. 打分层:单独加密口径(用户拍板,放弃"首期不打分"方案)

- **一次调用四件事**:重要性(对币圈整体,1-10)+ 方向(利多/利空/中性,对币圈整体)+ **提及币种清单** + **币圈事务判定(是/否)**。仍用 v4-flash 批量,成本与宏观打分同级。
- **币圈事务判定(用户点名的"隐形闸门",08-09 补)**:加密源也大量转载纯宏观新闻(美联储/CPI/地缘)。判"非币圈事务"的新闻**不进加密事件挂接**(零调用盖章留痕,同黑名单路径),加密快讯页照常显示——不入池≠丢弃。币圈自己的监管/ETF/大所动态属币圈事务,照常入池。
- **币种提取(用户拍板纳入首期)**:模型判断"这条新闻实际在说哪几个币",归一化成大写代码(如 SOL、ARB),落"新闻↔币种"对照表。理由:B 反查若靠正文全文搜,会被 OP/NOT/PEOPLE 这类"既是币名又是英文单词"的代码大量误伤;模型语义判断零额外调用成本。**不做每币单独方向判断**(归因场景币价自己会说话)。
- **币安没上的币怎么办(用户点名,不扩大化)**:存代码字符串本身,不限于币安全集;"币安可交易"是入库后拿现有 symbol 全集(425 现货+531 永续)机械查表打的是/否标记。B 永远从币安异动币反查,该方向必然命中;反方向只是可交易标记为否,不影响任何流程。不做币名词典、多交易所映射、别名解析;校准期抽检归一化错误率,不行再议。
- **提示词单独一版**,校准基准换成币圈事件谱(监管/ETF/黑客/上新/解锁/大所动态…),与宏观口径互不沾染。校准流程照抄一期:上线即跑,头 2-3 周并进用户现有每日 DeepSeek 复核环节抽看,认可后分数才投入使用。
- **加密新闻不进**宏观的行为分类、has_news、待标注候选——market 字段一刀切开,宏观线零污染。

## 3. 挂接:加密不设分数闸,真正的闸是语义闸(用户拍板+加码)

宏观闸门(≥6 或未评分)是为 1500-1800 条/天设的;加密线 200-300 条/天,**不按分数拦**。但闸门并非没有——**加密线的闸是语义闸:币圈事务(§2)才考虑挂接**,加密源转载的纯宏观新闻在闸外。币圈事务条条过模型考虑挂接。连带三个零件:

- **免闸关键词在加密线无闸可免**,该字段在加密事件上只剩一个职责:沉睡监听词(见 §4)。
- **分数的职责缩小为**:推送阈值(WeCom 恢复后才用)+ 列表排序参考。启不启用都不在小币链路上。
- **挂接分流按 market**:加密新闻的调用里只见活跃加密事件,宏观新闻只见宏观事件;**人工跨挂不拦**(BlockBeats 报了美联储大事想挂宏观事件,工作台随便挂)。对称地,金十偶报币圈新闻走宏观线,想进加密事件也靠人工跨挂,不做机制。

## 4. 事件池与页面

- **主表零新建**:research_events.event_type 加 `crypto` 值;挂接表、合并、关闭原因、双轨留痕(auto/human、模型原判保留)全部照旧。
- **立案纯人工**:加密快讯页行内"立案/挂接"入口(加密没有标注页,此入口顶上)+ 研究工作台手选。强制 ≥1 条新闻、active/closed 两态、关闭人拍板。
- **事件↔币种自动派生**:事件涉及哪些币 = 时间轴新闻提及币种的并集,读时派生,不落库不手填(符合一期"挂接表不存业务数值"铁律)。
- **沉睡监听(用户否决币种代码匹配方案)**:一条新闻常提多币、大币躺枪,且 SUI 这类币可同时有多条事件线,币种匹配分不清归属。改为照抄宏观机制——**事件关闭时人工留沉睡关键词,文本匹配**("SUI 生态基金"与"SUI 解锁"各归各词,精度人控)。
- **关闭提醒(用户加码,宏观加密一体)**:关闭事件时若免闸/沉睡关键词为空,界面必须提醒补填或明确留空(2026-08-09 实测线上 8 个事件 7 个关键词为空,且 5 分美伊新闻正被闸门拦掉,免闸词缺位有实际证据代价)。
- **时间轴照旧继承 BTC 观测值徽章**:零成本;大盘型加密事件(监管/ETF)有意义,小币事件该列无意义、无视即可——单币观测值是 B 的活,不抢跑。
- **独立"加密快讯"页面(用户拍板)**:不与宏观新闻混页;宏观新闻页一动不动。工作台与事件列表加类型筛选,加密事件卡片显示派生币种标签。
- **WeCom 首期不做(用户拍板)**:每日清单不并入、即时推送不做,开关留着。
