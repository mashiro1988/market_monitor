## 0. 一句话定位

现有体系回答的是**向后看**的问题:价格动了,为什么?(窗口标注、行为段、台账)
本稿加的是**向前看**的研究线:什么事正在变得重要、什么叙事正在成形,**而价格可能还没反应**——先入池观察,等价格来验证,而不是等价格动了再回头找原因。

两条新线,共用一套底盘:

| 线 | 研究对象 | 回答的问题 |
|---|---|---|
| 一线·宏观事件池 | 事件(如"日本央行加息预期提前") | 哪些事本身重要,即使市场暂时没反应,也该提前入池盯着? |
| 二线·Web3 叙事发现 | 叙事(如"全球资产迁移到全天候链上交易") | 哪些新细分叙事在成形/增强?最可能影响哪些可交易资产?声量与价格是否正在验证? |

两条线的研究对象不同、提示词严格分开,但存储、审核、推送、成本控制全部共用。

## 1. 共同哲学(两条线通用,砍需求时以此为准绳)

1. **新闻是原料,事件/叙事才是产品。**每天 1500-1800 条新闻(实测,平日),产出必须是"少数值得研究的主题",不是更多信息。这和窗口标注"一个窗口只认一个 driver、同簇算冗余"是同一个思想,推广到没有价格窗口的场景。
2. **只判断值不值得看,不预测。**不判断影响多久、何时反应、涨还是跌。系统只回答:值得关注吗、为什么、新证据强化还是削弱了它、接下来看什么验证信号。
3. **允许不确定。**新闻可以暂不归类;可以同属多个事件;叙事可以没有合格的关联资产;置信度只有三档(0.9/0.65/0.3,沿用标注体系的现行约定,拒绝 0.82 这种伪精度)。
4. **市场反应永远来自价格体系,模型无权填写。**时间轴上的价格信息分两层,都是算/标出来的:**观测层**——每条新闻后 30 分钟的净变动,读时现算(复用台账现成的 forward_reaction),纯观测不背书因果,0.3% 这种够不着窗口门槛(0.5%)的小反应也看得见;**确认层**——该新闻被人工确认为某标注窗口的 driver,徽章才亮,显示品种与涨跌幅。一层管全覆盖,一层管高置信。(边界:确认层只覆盖 BTC 与纳指;观测层默认也先做这两个品种,要不要扩展见 §6。)
5. **模型是标注助理,人工确认才是真值。**沿用标注三件套模式:模型原判(auto_*)与人工终判分轨保存,加提示词版本戳,改判要写原因。这些留痕就是未来微调本地小模型的底稿——没有人工确认,拿模型输出训练只是蒸馏外部大模型。
6. **每引入一个新组件都是运维负债。**单进程小服务器,能用现有零件的绝不新造(宏观线只新增两个概念:事件池、事件时间轴,见 §4)。

## 2. 一线:宏观事件池(v0.2,按 2026-07-28 用户反馈简化)

### 2.1 要解决什么

标杆案例(验收时就用它):日本央行第一次释放可能提前加息的信号,市场没反应。现有体系此时完全沉默——没有价格窗口,就没有标注,这条新闻打完分就沉底了。等第二次、第三次确认出现、价格真动起来,窗口标注才会回头把它认出来,但那时已经是"解释",不是"预警"。

事件池要做的:第一次信号出现时立一个事件,后续每条相关新闻按时间挂上去。人打开的不是 1500 条流水,而是一条条**事件时间轴**:什么时候出的第一条信号、中间攒了哪些证据、哪几条真的砸出过价格反应。

它与 Phase 4"应响未响"的关系:Phase 4 是瞬时快照(这条新闻 30 分钟没反应),事件池是纵向追踪(这件事持续重要而市场持续不理)。后者包含前者的使命,所以 Phase 4 并入本稿。

### 2.2 事件长什么样(v0.2 简化版)

一个事件 = **名字 + 状态 + 一条时间轴**,没有别的了。

- **状态只有三个:候选区 → 进行中 → 已关闭。**日常只看"进行中"。不设"强化/削弱/矛盾"这类概念——每条新闻本来就带利多/利空方向标,时间轴上一眼看得出走向,不再造一层。也不设"休眠"状态:进行中事件长期没新证据,列表里显示"N 天无新证据"往下沉即可。关闭由人拍板,模型只能建议。
- **时间轴上的每条证据 = 一条新闻**,自带四样现成的东西:时间、利多/利空方向标、**观测值**(新闻后 30 分钟净变动,forward_reaction 现算——兜住 0.3% 这类不过窗口门槛的反应)、**确认徽章**(被人工标为某窗口 driver 才亮,显示品种与涨跌幅)。模型无权填写任何一样。
- **纠错机制与标注页同款:**模型的归类/命名是原判(auto),人可以改归属、改名、合并、拆分、拒绝候选、**手工立新事件**、手工把某条新闻挂上/摘下时间轴;原判与人改分轨保存 + 版本戳,改判写原因——照搬标注三件套的结构。

### 2.3 新闻怎么进来(核心改造:主题槽位换成事件池)

- **采集、打分、方向/量级:现状完全不动。**
- **主题(topic)改造成"从事件池里选"。**现行打标给每条新闻选一个固定 11 类主题(地缘冲突/美联储政策/通胀数据…),这层静态分类和事件重复——按用户拍板直接换掉:打标时把**活跃事件池摘要**(编号+名称+一句话)放进提示词,模型为每条新闻选"挂到哪个事件"或"不挂"。一次调用顺手完成归类,**不另设匹配批次**。
  - 旧主题字段退役为历史数据,不再写入;主题台账(Phase 1)随之冻结为遗留——它的唯一下游(Phase 4)本已并入本稿,由事件时间轴接替,无连带损失。
  - 标注页的主题下拉同步改为事件下拉(或先保留只读)。
- **闸门照用现成分数:**不是所有新闻都配挂事件,实测 ≥5 分约 700 条/天还偏多,具体线(以及"闸门放提示词规则里还是拆两段调用")定稿前用近 30 天分布校准。
- **不做实体抽取**(v0.1 提过,v0.2 砍掉):它本是为"大池子检索匹配"准备的对齐锚;归类改成事件池直选后,模型一次调用就看到全部活跃事件,不存在检索问题。转载/同一起源的判断,模型归类时顺带做、人工把关兜底,不建独立机制。

### 2.4 事件怎么立起来

- 过闸但没挂上任何事件的新闻,自然形成**缓冲区**(一个查询条件,不是新表)。
- 每天一批(强模型):从缓冲区找方向一致的线索,**建议**候选事件。门槛不只看条数:独立起源 ≥2(金十和 CNBC 转引同一场讲话只算 1 个)、证据不是单一转述、相对市场原有预期确有新变化。
- 候选一律进候选区等人确认;确认转"进行中"时回扫最近缓冲区,把此前散落的旧证据挂上。人也可以随时不经模型手工立事件。

### 2.5 人的日常动线

- **研究工作台**(标注页工作台模式的延伸,一个页面管两条线):处理候选区(确认/拒绝)、纠错(改归属/改名/合并/拆分)、手工立事件、手工挂/摘证据。
- **每日 WeCom 清单**(通道现成):新增候选 N、进行中事件有新证据 N、其中带价格反应徽章 N。
- 节奏与现有每日标注复核合并成一个复盘环节,不另起炉灶。

## 3. 二线:Web3 叙事发现

### 3.1 要解决什么

不做 Web3 新闻摘要,不盯 BTC/ETH 主流(现有行情与板块模块已覆盖)。要的是:**新的细分叙事在哪里成形,哪些可交易资产最可能受它影响,这个影响是否正在被声量与价格两个可审计维度验证**——目标是找到"可能还没完全反映在价格里的叙事及其高相关 Altcoin"。

### 3.2 叙事≠关键词聚类

"Robinhood 扩股票代币 + 链上股票永续放量 + 钱包并购金融基建 + 传统市场讨论 7×24"这组新闻,聚成"Robinhood、股票、RWA"三个词是失败的;合格的叙事表述是**一个正在发生的结构性变化**:"全球资产正在迁移至全天候链上交易基础设施"。模型必须回答:这些新闻共同指向什么变化?是全新叙事、已有叙事的子叙事、还是已有叙事的强化?

(这与一线"事件"的区别:事件有主体和时间线,叙事是资金认知的迁移方向。所以两条线提示词分开,但卡片结构、证据流水、状态机制完全同构。)

### 3.3 叙事 → 资产:必须给证据链

映射的目标不是"新闻里出现过的 Token",而是"最可能因该叙事获得使用、收入、资金流或市场关注的资产"。每个资产:

- **关联类型五选一:**直接受益 / 基础设施受益 / 生态映射 / 情绪映射 / 负面关联(被替代、被分流)。
- **关联路径写成链:**叙事 → 中间机制 → 该资产如何受益,一步步写出来。只给"相关度 85 分"不给路径的输出一律不合格。
- **技术关联 ≠ 代币能捕获价值**,基础设施类必须追问一句"价值落到 Token 上吗"。
- **是否可交易是查表字段:**拿现有 Binance symbol 全集(425 现货 + 531 永续)机械匹配,不劳模型,不允许"unknown"。
- 允许输出**"本叙事暂无合格资产"**——强行配对是污染。

### 3.4 验证怎么做(v0.2:与宏观线同构,第三方榜单降为旁证)

结构照搬宏观线——多源新闻聚成叙事时间轴,判断只用两样**我们自己可审计**的数据:

1. **声量 = 自己聚合的新闻。**起步接 2-3 个 Web3 快讯源(BlockBeats、PANews、Foresight News,接入方式先实探;后续可加 Binance 官方公告)。叙事时间轴上"几家独立信源、多少条、持续几天"就是声量——与宏观线数独立起源是同一套逻辑。起步就要 2-3 家的原因:只接一个源时"新闻多"分不清是市场真热还是编辑勤快。
2. **价格/市值 = 关联资产的实际变化。**映射出的资产看价格与市值变化(绝对 + 相对 BTC/所在板块的超额),数据全是现成管道:板块轮动(425 现货+531 永续)+ CMC(cmc_client 已接入)。

第三方热度指标一律只做**旁证列**——页面上展示,判断逻辑不引用:

- Binance 匿名榜单(社交热度/Topic Rush 净流入):接口无文档、无服务承诺、口径黑箱、成交类数字可能含刷量——不可审计的数据不配当判断依据;
- CMC 热度(trending/most-visited 等):正式商业接口、项目已有集成,可信度高一档,但仍是第三方口径,同样只旁证(现有套餐覆盖哪些热度端点,spec 阶段实探)。

官方公告、文档、合作动态等定性核实,放进每日复盘环节人工点检,结论记回时间轴——这也是最值钱的训练数据。X 付费搜索、Dune(密钥泄露前科)、Token Terminal 等链上 API 全部暂缓,见负面清单。

### 3.5 状态四象限(声量 × 价格,只描述不荐买卖)

两个可审计维度直接落出四种状态:

| 新闻声量 | 关联资产价格/市值 | 读法 |
|---|---|---|
| 多 | 没动 | **潜在未定价——重点研究对象** |
| 多 | 大动 | 已在定价,追踪确认 |
| 少 | 大动 | 价格先行,查我们信源是否漏了信息 |
| 由多转衰 | 仍在高位 | 叙事退潮与价格背离 |

系统到此为止,不输出买卖建议。

## 4. 融合清单:旧零件直接用,新概念只有三个

**直接复用(不新建):**

| 需要的能力 | 用什么 |
|---|---|
| 采集/去重/回补 | 现有 4 源管道,5 分钟扫描 |
| 单条评判 | llm_importance + 方向/量级(全量在跑);主题槽位改造为事件直选(§2.3) |
| 双轨留痕模式 | 照搬 auto_news_roles / news_roles / prompt_version 三件套结构 |
| 价格反应·观测层 | theme_ledger.forward_reaction(读时现算,新闻后 30 分钟净变动,不落库) |
| 价格反应·确认层 | 反查已标注价格窗口(news_price_annotations.news_roles 里该新闻被标 driver) |
| Web3 价格验证 | 板块轮动数据(12 组/45 类)+ symbol 全集查表 |
| 推送 | 现有 WeCom 告警通道 |
| 成本分工 | v4-flash 管批量匹配,v4-pro 只碰候选新事件/叙事、合并拆分、高分歧样本(对齐现行打分/标注分工) |
| 审核界面 | 一个研究工作台,两条线共用(标注页工作台模式的延伸) |
| 数据保留 | 被事件/叙事引用的新闻加清理保护(扩展现有"标注引用保护") |

**新增概念(宏观线仅此两个;Web3 线待审后另计):**

1. **事件池**——事件的持久容器,三态生命周期(候选区/进行中/已关闭)。一张主表按类型区分两条线,不建两套。
2. **事件时间轴**——新闻挂到事件上的只增不改挂接记录;时间、方向标、价格反应徽章全部来自现成字段,时间轴本身只是挂接关系。

**刻意不做(负面清单):**

- 不建向量数据库(活跃池几十个,提示词直带摘要;池子过千再议);
- 不做全网 X 监听;受限搜索也暂缓;第三方热度榜(Binance 匿名榜单、CMC trending)只做旁证列,不进判断;
- 不做实体抽取(归类改为事件池直选后没有用武之地);
- 不给证据再分"强化/削弱/矛盾"(新闻自带利多/利空方向标,时间轴一眼可见);
- 不设休眠状态(用"N 天无新证据"排序体现);事件关闭由人拍板,模型只能建议;
- 不设"投资者三问"结构化字段(为什么重要/新增了什么/观察点),事件只有名字+状态+时间轴;
- 不让模型填价格反应(观测层机器现算,确认层只认已标注窗口);
- 不建第二个审核界面;
- 不预测持续时间/方向/时点;
- MVP 不接链上数据 API;
- Phase 4 不再单独开工。

## 5. 分期(思路级)

- **一期·宏观事件池:**闸门 + 打标调用改造(主题槽位→事件池直选)+ 事件池与时间轴 + 候选事件日批 + 研究工作台 + 每日 WeCom 清单 + 价格反应两层标记(观测层 forward_reaction 现算 + 确认层标注窗口反查)。验收金标准:回放 BOJ 案例历史新闻,系统应把加息线索聚成一条事件时间轴,每条证据带观测值、真砸出行情的那几条亮徽章,全程留痕可审。
- **二期·Web3 叙事:**2-3 个中文快讯源接入(BlockBeats/PANews/Foresight,接入方式先实探,这是二期第一个外部风险点)+ 叙事池复用事件池底盘 + 资产映射证据链 + 声量×价格四象限 + 第三方热度旁证列。每日只出 3-5 个候选叙事、每叙事最多 5-10 个候选资产。
- 一期先行的理由:零新外部依赖(全部现有数据源),而二期至少要探一个新源;且一期把事件池/时间轴/工作台这套共用底盘建好,二期是往里加第二种类型。

## 6. 悬而未决(定稿前要一起定的)

1. 宏观闸门的具体线(≥5 约 700 条/天偏多,用近 30 天分布校准),以及闸门落在哪:提示词内规则(低分默认不挂)还是拆两段调用;
2. 活跃池的定义(进提示词的是哪些:进行中全部 + 候选区全部?已关闭要不要留一行摘要防重建?);
3. 旧主题字段与主题台账的处置:冻结留查即可,还是连脚本一起下线;
4. 事件列表排序(最新证据时间倒序?要不要人工置顶?);
5. 打标改造的过渡方式(新旧字段并行核对几天再切,还是直接切);
6. 三个 Web3 快讯源(BlockBeats/PANews/Foresight)的接入方式与稳定性实探;CMC 现有套餐覆盖哪些热度端点;
7. 每日复盘环节怎么和现有标注复核合并(顺序、时长、WeCom 提醒格式);
8. 事件/叙事的命名规范(中文名为主?带不带日期前缀?);
9. 观测层品种范围(默认 BTC+纳指;要不要扩展到其他已采集品种如美元指数、金银油)。
