## 0. 一句话定位

事件池 = **人立案、机器挂证据、价格来验证**:你确认重要的事立成事件,系统把后续新闻自动挂成时间轴,每条证据带机器算的价格反应(观测值 + 确认徽章),全程留痕可审。

## 1. 铁律(权限边界,实现时任何取舍以此为准)

- 模型只有两种权力:**挂接权**(把过闸新闻挂到某个进行中事件,或不挂)、**建议权**(立案时建议免闸关键词,人确认才生效)。
- 模型没有:立案权、关闭权、重开权、合并/拆分权、价格填写权。
- 事件 = 名字 + 状态(两态)+ 时间轴。仅有的附加是**运维元数据**:免闸关键词(路由配置,决定新闻要不要送去让模型看,不描述事件本身)与留痕字段。继续不做任何语义/判断字段(投资者三问、强化/削弱、休眠态)。
- **人的动作永远畅通**:手工挂接/立案无视闸门与黑名单。
- 时间轴展示的时间、方向标、观测值、确认徽章全部从新闻表/标注表/价格表**读时派生**,挂接表一概不存业务数值。

## 3. 数据模型

### 3.1 `research_events`(新表:事件)

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 事件编号,提示词与界面里的 #17 |
| event_type | VARCHAR(16) | 固定 `macro`;二期叙事共用本表时加 `narrative`(思路稿 §4"一张主表"承诺) |
| name | VARCHAR(80) | 事件名(人起/人改的终值)。命名规范只作工作台占位提示:一个"待重定价的变量"一个事件;中文短名 ≤20 字、不带日期、主体+变化方向 |
| status | VARCHAR(10) | `active` / `closed` 两态 |
| gate_keywords | TEXT NULL | 免闸关键词,顿号分隔,人工确认后落库;可空 = 不免闸(§5) |
| merged_into_id | INTEGER NULL | 合并时指向并入的事件 |
| closed_reason | TEXT NULL | 关闭原因,人写;合并关闭时写"合并入 #N" |

| created_at / updated_at / status_changed_at | DATETIME | 时间戳(naive UTC,项目惯例) |

### 3.2 `research_event_links`(新表:时间轴 = 挂接记录)

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| event_id | INTEGER | 当前归属事件;(event_id, news_id) 唯一索引 |
| news_id | INTEGER | news_items.id |

| confidence | FLOAT NULL | 三档 0.9/0.65/0.3,仅 auto 挂接有;人工挂接 NULL(不适用) |

一条新闻:模型最多挂**一个**事件;人工可以挂多个(表结构天然支持,思路稿"可同属多个事件"由人工路径实现)。

### 3.3 `news_items` 加一列

`event_linked_at DATETIME NULL`——挂接处理游标,空 = 待处理,盖章 = 已处理。**四种处理结果都盖章**:模型挂上 / 模型判不挂 / 不够格(没过闸也没命中关键词,不发调用直接盖)/ 黑名单命中(同前)。游标因此是纯粹的待办队列,不需要任何时间窗过滤;回扫 = 清游标(§6.3)。**上线迁移时对存量新闻一次性盖章**(历史默认出池,要历史靠回扫召回)。这是对现有表的唯一改动。

### 3.4 迁移

新表由现有 `create_tables`(Base.metadata.create_all)自动建;`event_linked_at` 加进 `database._ensure_sqlite_schema` 的 news_items 补列块。全部幂等,无一次性数据迁移。

## 4. 挂接调用(新增的第二段 LLM 调用)

### 4.1 触发与资格

- 挂在现有 5 分钟扫描 tick 内、`_tag_new_news` 之后新增 `_link_new_news`(services/scan_runtime.py),**不新增调度任务**;`EVENT_LINK_ENABLED=0` 或**活跃池为空**时整段跳过,零调用。
- 每轮捞 `tagged_at` 非空(打标在评分之后,保证"未评分"确实是评分失败而非还没轮到)且 `event_linked_at` 为空的新闻,上限 200 条/轮(与打标的每轮 limit 同量级,兜住深回扫大批量时单轮耗时)。对每条判定(全部代码判定,可审计):
  1. 黑名单命中(§4.4)→ 盖游标跳过,不发调用;
  2. 没过闸——`llm_importance < 6` 且非 NULL 且未命中任何进行中事件的免闸关键词(§5)→ 盖游标跳过,不发调用;
  3. 其余(≥6 / 未评分 / 命中关键词)→ 进 LLM 调用。
- 批大小沿用 `DEEPSEEK_BATCH_SIZE=12`,模型 v4-flash(`DEEPSEEK_MODEL`)。稳态下每轮只有 4-5 条新新闻,单轮 1-2 批。

### 4.2 闸门线校准依据(2026-07-28 线上库,近 30 天)

全量 1199 条/天;各线放行量与 driver 召回(用 104 条标注中 71 条人工确认 driver 反测):

| 闸门 | 放行量/天 | driver 召回 |
|---|---|---|
| ≥5 | 517 | 90% |
| **≥6(本稿)** | 387 | 87% |
| ≥7 | 266 | 82% |
| 加"未评分"放行 | +122 | **96%(68/71)** |
| 对照:≥6 且量级非小 | 249 | 77%(被否:11 条真 driver 被模型打成"小") |

未评分必须放行:71 条 driver 里 6 条 `llm_importance` 为空(评分调用失败),纯数字闸门会无声丢弃。阈值是 config 常量,改线只动一处。

### 4.3 提示词形态与解析

- system:只做归类、不评判重要性、不确定就不挂;输出 JSON `{"items":[{"id": 新闻id, "event_id": 事件id或null, "confidence": 0.9|0.65|0.3}]}`。
- user 两块:**活跃池摘要**(每事件一行:编号 + 名称 + 首条证据标题(定义锚,不随时间漂移)+ 最近证据日期)+ **本批新闻**(id / source / title[:160] / content[:200],与打标同口径)。
- 解析层照搬 `news_tagging._parse_tagging_response` 的防幻觉套路:新闻 id 必须在本批内、event_id 必须在活跃池内、confidence 必须是三档之一,非法条目整条丢弃;**只有合法解析的条目盖游标**(含明确"不挂"),被丢弃的下轮自动重试;整批调用失败不盖游标、下轮重来,不影响打标已落库的成果。
- `EVENT_LINK_PROMPT_VERSION` 版本戳随每条 auto 挂接落库(留痕三件套之三)。

### 4.4 黑名单(固定栏目过滤)

config 新增 `NEWS_EVENT_LINK_BLACKLIST`:人工维护的(来源, 标题正则)清单,命中直接盖游标跳过、不发调用。起步两条(线上库 30 天高频重复实测):

- `("jin10", r"^金十数据整理：")`(每日大宗商品/热门ETF/A股盘前/特朗普24小时等系列,合计约 76 条/月过闸)
- `("jin10", r"^金十数据全球财经早餐")`

**禁止按频率自动生成**:同一查询里 `FinancialJuice` 前缀是该源所有新闻的统一开头、"据伊朗媒体Fars News"是真新闻,自动拉黑必误杀。黑名单只挡挂接,不影响打分/打标/展示。

### 4.5 成本

稳态约 43 次调用/天、13 万 token/天(flash 档),另加每次立案一次关键词建议调用,合计忽略不计;无新增定时 LLM 任务。种子期深回扫 14 天是一次性开销:清出的新闻里过闸的约 7 千条,百万 token 级,flash 档几元,分批 3 小时内消化完。

## 5. 关键词免闸(闸门旁路)

### 5.1 规则

- `gate_keywords` 命中**任一**词(或的关系)即免闸;匹配范围 = 标题 + 摘要(content[:200]),英文不分大小写。
- **免闸 ≠ 指定归属**:命中只是让新闻有资格被挂接模型看到,挂到哪个事件(或不挂)仍由模型对整个活跃池自由判断,人工照常纠错。所以关键词写宽的代价只是多几次便宜调用,不会造成错挂。
- 黑名单优先级最高(固定栏目永远进不来)。
- 只有**进行中**事件的关键词参与免闸;已关闭事件的关键词走沉睡监听(§7),不进挂接。
- 关键词在任何状态下可编辑(这是沉睡监听吵人时的手动阀门);合并 A→B 时 A 的关键词并入 B 并去重,防止合并弄丢监听。
- **改关键词只对之后的新闻自动生效**(已盖章的不会自动重考);要它追溯既往,保存时勾选"回扫 72h"(与立案/重开的自动回扫同一机制),更早的用深回扫按钮。

### 5.2 AI 建议、人确认

立案(或事后编辑)时可点"AI 建议":一次 flash 调用,输入 = 事件名 + 种子新闻标题与摘要,输出 3-6 个建议词预填输入框,**你改完点保存才落库**。建议提示词写死取词规则(同时作为输入框占位提示):

1. 实体词优先,中英别名都要("苹果、Apple、iPhone"——金十是中文、financialjuice 是英文,只写中文漏一半信源);
2. 每个词**单独**命中时应大概率与本事件相关("植田"行,"加息"不行——会把美联储的全捞进来);
3. 禁单字与泛词("油""美股""关税"会让闸门虚设);
4. 3-6 个封顶。

建议调用即用即弃不留痕(关键词是人的配置,不是模型判断);提示词常量 + 版本注释放 service 文件,与挂接提示词同处维护。

## 6. 事件生命周期与操作

### 6.1 立案(仅人工,两条路径,强制 ≥1 条新闻)

- **标注台顺手立**(`created_from=annotation`):标注页 driver 新闻行的"挂到事件…"下拉含"新建…"项——你每天确认 driver 时价格已证明它重要,顺手一点即立案。
- **工作台手工立**(`created_from=manual`):缓冲区浏览/搜索中勾选新闻 → 起名 →(可选 AI 建议关键词)→ 立案。
- 事件出生即 `active`;立案自动触发 72h 回扫(§6.3)。

### 6.2 全部人工操作与留痕规则

| 操作 | 行为 | 留痕 |
|---|---|---|
| 改名 | 改 name | updated_at |
| 关闭 | status→closed,写 closed_reason | status_changed_at |
| **重开** | status→active;免闸恢复;自动回扫 72h | status_changed_at |
| 合并 A→B | A 的未摘下挂接 event_id 改 B(撞唯一索引即跳过);A 关键词并入 B 去重;A→closed,merged_into_id=B,closed_reason="合并入 #B";A 的已摘下记录留在 A(审计痕迹不迁移) | 同上 |
| 拆分 | 选中若干挂接改到新事件(先立新事件再批量改归属) | 同改归属 |
| 改归属 | 挂接 event_id 改新值;auto_event_id 保原判;link_source→human | updated_at |
| 摘下 | detached=true + detach_reason,**不删行** | 同上 |
| 手工挂 | 新建挂接,link_source=human,无视闸门/黑名单;可给一条新闻挂多个事件 | created_at |

### 6.3 回扫 = 清游标(一套代码,无第二条调用路径)

把范围内**当前够格**(过闸或命中关键词、不在黑名单)且**无未摘下挂接**的新闻的 `event_linked_at` 清空,下轮 tick 常规挂接对着**更新后的池子**自然重收,一套代码、无第二条调用路径。立案/重开自动清最近 `EVENT_BACKSCAN_DEFAULT_HOURS=72` 小时;事件详情页"深回扫"按钮可传天数(BOJ 这类你知道线索早就有的手动往回捞)。小范围回扫下 1-2 轮 tick(5-10 分钟)挂满;深回扫大范围按 200 条/轮分批消化(14 天约 7 千条过闸新闻 ≈ 3 小时),详情页显示"回扫进行中(剩 N 条)"递减。

### 6.4 缓冲区

不是表,是查询:过闸(§4.1 第 4 条)+ 不在黑名单 + 无未摘下挂接。工作台可按日期/最低分/关键词/仅看已确认 driver 过滤。

## 7. 沉睡监听(旧事重提)

用户哲学:苹果供应链调价两年来一次,来的那一下要**立刻**认出来——"同一个亏不吃第二次"必须覆盖休眠的线。

- 已关闭事件的 gate_keywords **不删不失效**,每日与昨日新闻做纯文本匹配(现算,不落库,零 LLM);命中**不进挂接调用**(事件已关闭,模型无权挂,铁律不动)。
- 出口两个:08:10 WeCom 清单加行"已关闭事件『X』的关键词昨日命中 N 条";工作台"旧事重提"视图列最近 7 天命中已关闭事件的新闻。
- 处理动作:**重开**(§6.2,时间轴同一条——两年前的证据链、当年徽章原地全在,这就是历史知识的载体)或修剪该事件关键词(嫌吵的阀门)。

## 8. 价格两层标记

### 8.1 观测层(机器现算,模型无权填写)

新函数 `observed_reaction`(services/theme_ledger.py,与 `forward_reaction` 并列;**冻结的旧函数一行不动**):

- 基线 = 新闻**前**最近一个快照(容差 6 分钟内);终点 = 新闻后 `EVENT_OBS_REACTION_MINUTES=10` 分钟内最后一个快照;净变动 =(终点−基线)/基线。
- `now < 新闻时间 + 10min` → 返回 pending,前端显示"计算中",不给半熟数;无基线或无终点(数据洞)→ "—"。
- 显示带**实际分钟数**(基线到终点的真实跨度,因基线在新闻前、常为 11-15 分钟):"12min +0.31%",不谎报口径。
- 品种 `EVENT_OBS_SYMBOLS=("BTC/USDT",)`,扩品种改一行。
- **读时现算,不落库**(快照永久保留(§12),历史任何时点可算);时间轴接口一次批量捞该事件时间范围的快照、内存逐条算(照搬 annotation_service `_load_reference_rows` 套路),不逐条查库。

### 8.2 确认层(标注反查徽章)

时间轴读取时把全部标注的 `news_roles` 一次载入解析,新闻 id 命中 **driver** 的点亮徽章,显示品种 + 窗口涨跌(取标注行自存的 change_pct,不依赖快照,永久可显)。

### 8.3 评分失手徽章与清单

定义:存在未摘下挂接的新闻,`llm_importance` 非空且 < 闸门线。时间轴行显示徽章(如"3分→已挂"),工作台给失手清单——这是打分提示词校准的素材,并入现有每日标注复核环节;失手积累还提示你该给哪些事件补关键词。

## 9. 工作台与接口

### 9.1 新页面"研究"(frontend/src/pages/ResearchPage.tsx,标注页工作台模式)

- **进行中列表**(默认):按最新证据时间倒序(最新证据 = 未摘下挂接对应新闻的最大 timestamp),行内 = 事件名 / 证据总数 / 今日新增(北京日,与行为面板同口径)/ 确认徽章数 / "N 天无新证据";不做置顶。已关闭折叠在底部,支持按名称+关键词搜索(含已关闭,SQLite LIKE 即可)。
- **事件详情**(点行展开):时间轴逐条 = 北京时间 / 来源 / 标题 / 方向标 / 观测值 chip / 确认徽章 / 评分失手徽章,行操作 = 改归属 / 摘下;头部 = 改名 / 关键词编辑(含 AI 建议)/ 关闭 / 重开 / 合并到… / 深回扫;回扫进行中提示。
- **缓冲区**页签:过滤(日期/最低分/关键词/仅看已确认 driver),勾选 → 立事件 / 挂到事件。
- **旧事重提**页签:近 7 天命中已关闭事件关键词的新闻。
- 顶部两个数字(并行期观察,§13):挂接率 / 人工纠错率(当日)。

### 9.2 标注页接线(AnnotationsPage.tsx)

driver 新闻行:已挂事件的**只读徽章 + 跳转**(取代旧主题下拉的位置)+ "挂到事件…"下拉(活跃事件 + 新建…)。纠错写操作集中在研究页,标注页只有这一个快捷挂接入口。

### 9.3 API(沿用 /api/ 风格、鉴权与统一错误格式)

| 路由 | 用途 |
|---|---|
| GET /api/research/events?status=&q= | 列表(含计数/徽章/今日新增/N 天无新证据) |
| POST /api/research/events | 立案(name + news_ids ≥1 + gate_keywords? + created_from) |
| POST /api/research/events/suggest-keywords | AI 建议关键词(name + news_ids → 词列表,不落库) |
| PATCH /api/research/events/{id} | 改名 / 关键词 / 关闭(reason)/ 重开 / merge_into |
| POST /api/research/events/{id}/backscan | 回扫 {days} |
| GET /api/research/events/{id}/timeline | 时间轴(观测值/徽章现算) |
| POST /api/research/links | 手工挂接 {event_id, news_id} |
| PATCH /api/research/links/{id} | 改归属 {event_id} / 摘下 {detached, reason} |

| GET /api/research/revival | 旧事重提(近 7 天) |
| GET /api/research/stats | 挂接率 / 纠错率(工作台顶部) |

## 13. 过渡与上线步骤

1. **部署**:迁移自动(§3.4)+ 存量新闻游标一次性盖章(§3.3,防上线后 tick 对 6 月以来 6.6 万条历史突发大扫描);`EVENT_LINK_ENABLED=1`。此时池子空,挂接零调用。
2. **种子池**(上线首日,约 20-30 分钟人工):工作台"过去 14 天已确认 driver"过滤(预计 20-30 条)→ 人工归组立案 8-12 个事件 → 填关键词(苹果调价、客机这类失手线优先补)→ 各深回扫 14 天。全程无模型参与,与正式运行规则一致。
3. **并行 7 天**:打标照旧写 topic(不动提示词);每天看工作台顶部两数——挂接率(过闸新闻里模型挂上的占比,太低 = 太保守或池子太空)、纠错率(模型挂的里被你改归属/摘下的占比)。
4. **切换**:连续 3 天纠错率 <20% 且无整批调用失败 → 从打标提示词删 topic 槽位、停写 `news_items.topic`;news_tagging.py 头注释记录日期与原因(打标无版本戳列,不新增列)。同步执行思路稿既定处置:NEWS_TOPICS/theme_ledger 主题函数/backfill_ledger.py 原地保留并标"已冻结·遗留";`tag-options` 的 topics 键与前端 topic 下拉退役(标注页位置由事件徽章接替,§9.2)。
5. **回滚**:`EVENT_LINK_ENABLED=0` 停挂接;已建表与已挂数据原地保留,不回滚 schema。
